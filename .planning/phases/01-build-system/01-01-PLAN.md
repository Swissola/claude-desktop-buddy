<objective>
Stand up a dual-environment PlatformIO build on M5Unified + M5GFX from the single existing
src/ tree, add the 8MB StickS3 partition table, and remove the board-specific M5StickCPlus
library — without changing the m5stickc-plus env's hardware/build configuration.

This is the BUILD SYSTEM phase only. It does NOT fix source-level API errors (Phase 3) and
does NOT write compat.h (Phase 2). The acceptance bar for the new StickS3 env is that
`pio run -e m5stack-sticks3` reaches the source-compile/toolchain stage with dependencies and
the partition table resolving. Source compile errors against the old M5StickCPlus API are
EXPECTED at the end of this phase and are deliberately deferred.

Purpose: Establishes the one-tree / two-board foundation every later phase builds on.
Output: A refactored platformio.ini ([common] + two envs) and a new partitions_8mb.csv.
</objective>

    - The final partition's (offset + size) equals 0x800000 (8MB) exactly.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PlatformIO registry → local build | External library packages (M5Unified, M5GFX) are fetched and compiled into firmware |
| partition table → flash hardware | partitions_8mb.csv dictates the on-flash memory map; a wrong table can overflow flash or brick boot |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | lib_deps dependency sourcing (M5Unified/M5GFX) | mitigate | Pin to ^0.2.x and use the official `m5stack/` namespace + retained `bitbank2/`,`bblanchon/` packages; no unpinned or unscoped libs added |
| T-01-02 | Denial of Service | partitions_8mb.csv layout | mitigate | Offsets/sizes sum to exactly 0x800000 (validated); app0 0x10000-aligned; board_upload.flash_size=8MB matches the N8R8 module so the table cannot overflow real flash |
| T-01-SC | Tampering | PlatformIO library installs | mitigate | All four lib_deps are version-pinned, namespaced packages from the PlatformIO registry; PlatformIO libs are outside the npm/pip/cargo legitimacy-gate scope, so no blocking-human checkpoint is required, but the pins are the supply-chain control |
</threat_model>
