<objective>
Create `src/compat.h` — a board-agnostic compatibility header that re-creates the legacy
M5StickCPlus API names (`TFT_eSprite`, `TFT_eSPI`, `RTC_*TypeDef`) and `compat*` helper
functions on top of M5Unified + M5GFX, so the fork's ~3k lines of UI/render/power/RTC code
can compile against the new libraries in Phase 3 with mechanical call-site swaps only.

This plan delivers SHIM-01. It honors D-07 (start from PR #48's verbatim `compat.h`, extend
only as this fork's documented source inventory demands) and writes the FULL helper set now —
graphics typedefs, software RTC (D-01/D-02), AXP→`M5.Power`/`M5.Display` maps (D-03), the
D-04 safe stubs, `compatOnUsb`, no-op `compatLed` on StickS3 (D-06/RF-02), and
`compatChipTempC` (D-05) — every board-specific helper gated on `#if defined(BOARD_STICKS3)`
so the StickC Plus path keeps calling the native AXP192/RTC.

Purpose: Make Phase 3 (API Port) a sequence of mechanical edits by giving it a complete,
pre-compiled shim surface. Acceptance is narrow and specific (ROADMAP criterion 3): a TU
including ONLY `compat.h` (+ M5Unified/M5GFX) compiles clean under the StickS3 env.

Output: `src/compat.h` (the only net new file), proven via a self-cleaning compile probe.

SCOPE BOUNDARY (criterion 4 — do NOT cross): do NOT edit `src/main.cpp`, `src/buddy.*`,
`src/character.*`, `src/buddies/*`, `src/data.h`, `src/stats.h`, `src/xfer.h`. Do NOT remove
or alter the `class TFT_eSPI;` forward declarations at `buddy.h:11` and `character.h:27` —
those redeclaration-conflict fixes are Phase 3 (PORT-02). Swapping `M5.Axp.*`/`M5.Rtc.*`
call sites onto the helpers is Phase 3. This plan proves the shim COMPILES STANDALONE, not
that the whole app links.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bonded BLE host → device | The `{"time":[epoch, tz]}` JSON arrives over the NUS RX characteristic and seeds the software clock. This seam is PRE-EXISTING in `data.h::_applyJson` and is NOT modified by this phase. The NUS characteristics are encrypted-and-bonded (`ESP_GATT_PERM_*_ENCRYPTED`), so the time source is an already-authenticated peer. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | software RTC seed (`compatRtcSet` ← host `{"time":...}`) | accept | A malicious/garbled time only skews a cosmetic wall clock; no auth/session/expiry logic depends on it in this firmware. Value already bounded by `t[0].as<uint32_t>()` in the pre-existing `data.h` parser (untouched here). No host-side or parser changes in Phase 2. |
| T-02-02 | Denial of Service | `_compatTimegm` integer date math | mitigate | Use the verbatim PR #48 routine (no loops, fixed `mdays[]` table, `% 12` guards the month index) — bounded, branch-free arithmetic with no allocation or unbounded iteration; cannot hang or overflow into UB for `uint32_t`-ranged epochs. |
| T-02-03 | Tampering | type-correctness of D-04 stubs / unit shims | mitigate | `static inline` helpers with explicit return types; float-volts vs int-mV conversion centralized in `compatBatVoltage`/`compatVBusVoltage` (Pitfall 3) so no caller does a wrong-unit raw cast. Stubs return safe zero/no-op values, avoiding uninitialized reads. |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | N/A — this phase installs ZERO external packages. M5Unified/M5GFX were vetted and locked in Phase 1 (`platformio.ini`). RESEARCH "Package Legitimacy Audit" = Not applicable. No install task exists, so no legitimacy checkpoint is required. |
